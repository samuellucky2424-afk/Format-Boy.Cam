## PRO Mode Implementation Rules

- PRO uses `decart/lucy-2-5/realtime` through fal.ai. Do not use Morphly for new sessions.
- Never expose `FAL_KEY`, the Supabase service-role key, raw provider credentials, or admin credentials to the renderer.
- Browser access to fal.ai must use a short-lived realtime JWT minted by an authenticated Henshin server endpoint and restricted to the Lucy endpoint.
- PRO access requires both an active account-bound license and enough wallet credits.
- A PRO license is generated by an admin, assigned to an existing Henshin account, entered once by that user, and remains valid until revoked.
- Store license codes as secure hashes. Show the full generated code only once; regeneration replaces the previous code.
- The PRO credit rate is server-authoritative and configurable per license. Never trust a rate sent by the client.
- Default future PRO rate: 80 credits per second. The first negotiated client may use 46 credits per second.
- Fast mode remains Reactor X2 at 2 credits per second unless the user explicitly changes that product rule.
- Billing starts only after provider output is usable, is finalized atomically, and must reconcile interrupted/stale sessions.
- Preserve persisted Morphly sessions as historical records, but label them deprecated and never mint new Morphly credentials.
- All admin mutations must be performed through authenticated server APIs or SECURITY DEFINER RPCs, not direct privileged renderer writes.
- Admin credit changes, license changes, and payment decisions require an audit reason and an immutable audit record.
- Payment revenue must never sum different currencies into one unlabeled total.
- A user without PRO access must see a WhatsApp contact action for `237620124019` and must not receive a fal.ai token.
- Add focused tests for authorization, license redemption, rate selection, token restrictions, idempotent billing, and admin-only mutations.
- Use Bun commands for dependency installation, tests, linting, and builds.
